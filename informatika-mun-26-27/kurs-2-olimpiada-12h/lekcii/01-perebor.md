# Блок 1. Перебор и моделирование (часы 0–2)

**Цель:** Научиться оценивать, пройдёт ли перебор по времени, и перебирать «умно»: всё, что можно вычислить, — вычислять, а не перебирать.

## Лекция

### Сколько операций успевает компьютер

За 1 секунду: C++ — около \(10^8\)–\(10^9\) простых операций, Python — около \(10^7\).

Перед тем как писать решение, подставьте максимальные ограничения в сложность:

- \(n \le 20\) → можно перебрать все подмножества: \(2^{20} \approx 10^6\);

- \(n \le 8\)–\(10\) → можно перебрать все перестановки: \(8! = 40320\), \(10! \approx 3.6 \cdot 10^6\);

- \(n \le 5000\) → проходит \(O(n^2)\);

- \(n \le 2 \cdot 10^5\) → нужно \(O(n)\) или \(O(n \log n)\);

- \(n \le 10^{18}\) → только формула или \(O(\log n)\).

### Виды перебора

- **Вложенные циклы** — когда параметров 2–3 и они небольшие.

- **Подмножества через битовые маски**: число `mask` от 0 до \(2^n - 1\); элемент `i` взят, если `mask >> i & 1`.

- **Перестановки**: `itertools.permutations` в Python, `next_permutation` в C++.

- **Перебор ответа**: если ответ небольшой, перебираем его и проверяем.

### Главный приём: перебирать меньшее, вычислять остальное

Если в задаче два неизвестных и одно выражается через другое, перебирайте одно, а второе вычисляйте формулой. Это превращает \(O(n^2)\) в \(O(n)\), а \(O(N)\) — в \(O(\sqrt N)\).

Пример: пары \(a^2 + b^2 = N\). Перебирать обе переменные до \(\sqrt N\) — \(10^{12}\) операций при \(N = 10^{12}\). Перебирать только \(a\), а \(b = \sqrt{N - a^2}\) проверять — \(10^6\) операций.

### Моделирование

Иногда проще всего честно «прожить» процесс: шаг за шагом изменять состояние (время, позиции, счётчики).

Время удобно переводить в одну величину: `ЧЧ:ММ` → минуты `h * 60 + m`.

Ловушка: моделирование по секундам там, где событий \(10^{18}\), не пройдёт — тогда нужна формула.

## Разобранный пример: Сумма двух квадратов

Дано \(N\) (\(1 \le N \le 10^{12}\)). Сколько существует пар натуральных чисел \(a \le b\), таких что \(a^2 + b^2 = N\)?

| Вход | Выход |
|------|-------|
| `50` | `2` |
| `325` | `3` |
| `3` | `0` |

**Разбор по шагам:**

1. Наивно: два цикла до \(\sqrt N = 10^6\) — это \(10^{12}\) итераций, не пройдёт.
2. Перебираем только \(a\), пока \(2a^2 \le N\) (так как \(a \le b\)).
3. Вычисляем \(b = \lfloor\sqrt{N - a^2}\rfloor\) **целочисленно** (`math.isqrt`) и проверяем \(b^2 = N - a^2\).
4. Для 50: \(1+49\) и \(25+25\) → 2. Для 325: \(1+324\), \(36+289\), \(100+225\) → 3.
5. Ловушка: `int(sqrt(x))` с вещественными числами может ошибиться на 1 при больших \(x\).

```python
from math import isqrt

n = int(input())
cnt = 0
a = 1
while 2 * a * a <= n:
    rest = n - a * a
    b = isqrt(rest)
    if b * b == rest:
        cnt += 1
    a += 1
print(cnt)
```

### Игральные кубики

**Источник:** [ВсОШ, муниципальный этап 2024/25, 9–11 кл. (Казань, 5 декабря 2024)](https://tasks.olimpiada.ru/upload/files/tasks/73/2024/tasks-iikt-9-11-mun-belgor-24-25.pdf), задача A

Для каждого из \(n \le 10^5\) наборов из шести чисел определить, можно ли записать их на грани кубика так, чтобы суммы на противоположных гранях были равны (yes/no).

**Идея решения.** Перебирать все расстановки (6!/…) можно, но есть идея лучше: отсортируем числа. Если пары с равной суммой S существуют, то наименьшее число обязано стоять в паре с наибольшим (иначе сумма с ним меньше S). Проверяем a0+a5 = a1+a4 = a2+a3.

Эталонное решение: [`solutions/r_kubiki.py`](../solutions/r_kubiki.py)

### Все на съезд!

**Источник:** [ВсОШ, муниципальный этап 2024/25, 9–11 кл. (Москва)](https://vos.olimpiada.ru/upload/files/Arhive_tasks/2024-25/mun/iikt/tasks-iikt-9-11-mun-msk-24-25.pdf), задача 5

12 секций нужно разбить на 3 дня по 4 секции. Каждый из \(n \le 10^4\) участников выбрал 3 секции и в один день может посетить только одну. Составьте расписание с максимальным суммарным числом посещённых секций.

**Идея решения.** Различных разбиений всего \(\frac{12!}{(4!)^3 \cdot 3!} = 5775\) — их можно перебрать. Чтобы не проходить каждый раз по всем \(10^4\) участникам, сгруппируем одинаковые тройки (их не больше \(C_{12}^3 = 220\)). Итого \(5775 \cdot 220 \approx 1.3 \cdot 10^6\) операций. Чтобы не перебирать одно разбиение 6 раз, секция 1 всегда в первом дне, а наименьшая из оставшихся — во втором.

Эталонное решение: [`solutions/r_sezd.py`](../solutions/r_sezd.py)
