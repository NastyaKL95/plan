# Блок 4. Бинарный поиск и алгоритм Евклида (часы 6–8)

**Цель:** Искать в отсортированном массиве за O(log n), применять бинарный поиск по ответу и пользоваться НОД/НОК и алгоритмом Евклида.

## Лекция

### Бинарный поиск в массиве

Массив отсортирован → любое значение ищется за \(\log_2 n\) шагов (для \(10^6\) — 20 шагов).

`bisect_left(a, x)` — первая позиция, где `a[i] >= x`; `bisect_right(a, x)` — первая, где `a[i] > x`.

Количество элементов на отрезке [L, R]: `bisect_right(a, R) - bisect_left(a, L)`.

### Бинарный поиск по ответу

Если есть проверка `ok(x)` — «можно ли добиться результата x» — и она **монотонна** (для маленьких x да, для больших нет), то наибольший подходящий x ищется бинпоиском.

Шаблон «последний true»: `while lo < hi: mid = (lo + hi + 1) // 2; if ok(mid): lo = mid else: hi = mid - 1`.

Шаблон «первый true»: `mid = (lo + hi) // 2; if ok(mid): hi = mid else: lo = mid + 1`.

Главная ошибка — бесконечный цикл из-за неправильного округления `mid`. Проверяйте шаблон на массиве из 2 элементов.

### Вещественный бинпоиск

Для уравнений вида \(f(x) = C\) с возрастающей \(f\): делаем 100 итераций деления отрезка пополам — точность \(2^{-100}\) от длины отрезка, больше чем достаточно.

### НОД, НОК, алгоритм Евклида

\(\gcd(a, b) = \gcd(b, a \bmod b)\), \(\gcd(a, 0) = a\). Работает за \(O(\log \min(a,b))\).

\(\text{lcm}(a, b) = a / \gcd(a,b) \cdot b\) — сначала делим, потом умножаем (меньше риск переполнения).

Сокращение дроби: разделить числитель и знаменатель на НОД.

Евклид с вычитанием (\(a - b\) вместо \(a \bmod b\)) описывает путь в дереве Штерна–Броко — см. «Рациональное дерево».

## Разобранный пример: Ксерокопии

Нужно сделать n копий документа. Есть оригинал и два ксерокса: первый делает копию за x секунд, второй — за y. Копировать можно и с копии, но сначала нужна хотя бы одна копия. За какое минимальное время получится n копий?

| Вход | Выход |
|------|-------|
| `4 1 1` | `3` |
| `5 1 2` | `4` |

**Разбор по шагам:**

1. Первую копию делаем на быстром ксероксе: `min(x, y)` секунд. Дальше оба работают параллельно.
2. За t секунд они сделают `t // x + t // y` копий — функция **монотонна** по t.
3. Бинпоиском ищем наименьшее t, при котором `t // x + t // y >= n - 1`.
4. Ответ: `min(x, y) + t`. Для 5 1 2: первая копия 1 с, потом за 3 с делают 3 + 1 = 4 копии → 4.

```python
n, x, y = map(int, input().split())
first = min(x, y)
lo, hi = 0, (n - 1) * max(x, y)
while lo < hi:
    mid = (lo + hi) // 2
    if mid // x + mid // y >= n - 1:
        hi = mid
    else:
        lo = mid + 1
print(first + lo)
```

### Maximum Median

**Источник:** [Codeforces 1201C — Maximum Median](https://codeforces.com/problemset/problem/1201/C)

n нечётно, можно k раз увеличить любой элемент на 1. Какую наибольшую медиану можно получить?

**Идея решения.** Сортируем; важна только правая половина. ok(x): сумма `max(0, x - a_i)` по правой половине ≤ k. Бинпоиск по ответу.

Эталонное решение: [`solutions/cf1201c_median.py`](../solutions/cf1201c_median.py)

### Рациональное дерево

**Источник:** [ВсОШ, муниципальный этап 2024/25, 9–11 кл. (Казань, 5 декабря 2024)](https://tasks.olimpiada.ru/upload/files/tasks/73/2024/tasks-iikt-9-11-mun-belgor-24-25.pdf), задача C

Дроби строятся вставкой медиант (a+c)/(b+d) между соседями, начиная с 0/1 и 1/0 (дерево Штерна–Броко). Для дроби a/b (до \(10^6\)) вывести путь из букв L/R от корня 0/1.

**Идея решения.** Сокращаем дробь на НОД (8/6 и 4/3 — одна вершина). Первый шаг из 0/1 всегда R (к 1/1). Дальше — алгоритм Евклида с вычитанием: пока a ≠ b, если a < b — шаг L и b −= a, иначе шаг R и a −= b. Чтобы не делать \(10^6\) вычитаний, вычитаем сразу q раз, где q — частное (как в обычном Евклиде). 3/4 → RLRR.

Эталонное решение: [`solutions/r_derevo.py`](../solutions/r_derevo.py)
