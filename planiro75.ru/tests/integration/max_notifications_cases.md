# Интеграционные тест-кейсы: MAX уведомления

## Подготовка

- Включить MAX (`PLANNER_MAX_TOKEN`, при необходимости `PLANNER_MAX_CHAT_ID`).
- Заполнить пользователю `max_chat_id` в профиле (или использовать fallback `max.chat_id`).
- Убедиться, что работает воркер `public/cron/max_notify_worker.php`.

## 1) Назначение исполнителя

- Создать задачу.
- Сменить исполнителя на другого пользователя.
- Ожидание:
  - создается событие `task_assigned` в `notification_events`;
  - после воркера статус события `sent`;
  - в чате исполнителя есть сообщение "Вас назначили исполнителем".

## 2) Смена статуса

- Перевести задачу `new -> in_progress -> review`.
- Ожидание:
  - создаются события `task_status_changed` для релевантных получателей;
  - сообщения содержат старый и новый статус;
  - статус в очереди меняется на `sent`.

## 3) Смена дедлайна

- Изменить `due_date` у задачи.
- Ожидание:
  - создается событие `task_due_changed`;
  - в сообщении есть "Было/Стало";
  - после воркера событие `sent`.

## 4) Mention в комментарии

- Добавить комментарий с упоминанием пользователя.
- Ожидание:
  - создается событие `task_comment_mention`;
  - в сообщении есть задача и превью комментария;
  - автор комментария не получает сам себе уведомление.

## 5) Fallback на общий chat_id

- Очистить `users.max_chat_id` у тестового пользователя.
- Убедиться, что задан `max.chat_id` в конфиге.
- Сгенерировать событие (например, mention или назначение).
- Ожидание:
  - уведомление уходит в fallback-чат;
  - событие становится `sent`.

## 6) Алерты мониторинга

- Временно задать неверный токен MAX.
- Сгенерировать событие и запустить воркер.
- Ожидание:
  - событие уходит в retry/failed;
  - `GET /api/max_metrics.php` возвращает alert при `failed > 0`.

- Остановить cron/воркер и подождать порог stale.
- Ожидание:
  - `GET /api/max_metrics.php` возвращает alert про heartbeat/cron.
